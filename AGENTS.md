# codex-workforce

A workforce system for OpenAI Codex CLI, ported from claude-workforce
(github.com/odysseyalive/claude-workforce). Codex is the only supported host. Crush
compatibility was cut on 2026-11-11; the Crush probing remains historical discovery evidence,
not a product target.

## Current state: bare-metal senses

The claude-workforce sensory layer is wired into Codex sessions in this repository through
`.codex/hooks.json`. It is verified by `tests/`, by replaying real Codex rollouts, and by live
Codex sessions in this repository on 2026-11-11 and 2026-11-12. The hooks require the trust
step below, and the prompt, SubagentStart, Stop and SubagentStop payloads have all been
observed live, a generated custom agent has loaded by type, and a generated skill has loaded
by its `$cwf-` name. Seven upstream skills ship as `cwf-*` copies and are invoked with
`$cwf-<name>`, plus two authored here: `cwf-dev` (the port's own maintainer skill) and
`cwf-timezone` (rewritten because Codex does not read the `settings.json` upstream writes).
Ten Codex custom agents are generated into `.codex/agents/`.

| Codex event | Runs | Does |
|---|---|---|
| UserPromptSubmit, SubagentStart | `cwf/bin/cwf-hook prompt` -> `wf-task-tag` | tags the ask with the senses that settle it, writes the asks checklist, opens issues |
| Stop, SubagentStop | `cwf/bin/cwf-hook stop` -> `wf-turn-ledger`, `wf-widen`, juror | counts the turn's evidence, blocks a reply whose claims lack it, and on flagged turns asks a read-only `codex exec` juror |

The hooks only run after they are trusted: open `/hooks` in an interactive Codex session in
this repository and trust the four entries. Re-trust after any change to `.codex/hooks.json`.
The prompt hook checks this itself: when a codex-workforce entry's definition no longer matches
its `trusted_hash` in `~/.codex/config.toml`, the first prompt of a session shows a
`systemMessage` naming it. `python3 cwf/bin/cwf-hook trust-check .codex/hooks.json` prints
each entry's state and exits 1 when one needs `/hooks`. The hash format was reproduced from
Codex's own rows, not documented, so treat a check that cannot read the config as "unknown".
The hook commands find `cwf/` through `git rev-parse --show-toplevel`, so this directory must
stay a git repository.

### First live run

1. `CWF_DEBUG=1 codex` in this repository, then `/hooks`, and trust all four entries.
2. Ask, in one sentence and telling it not to look: *"Without running anything, is there a
   file named zzz-probe.txt in this repo?"*
3. Expect: a Stop block whose feedback starts "Stop hook feedback:", Codex continuing and
   enumerating (find, ls or rg), then a clean end with no second block.
4. Check `.codex-workforce/issues/` gained no issue from the feedback text, and
   `.codex-workforce/debug/<session>.jsonl` holds the raw payloads Codex sent.

### Session handoff

`RESUME.md` at the repository root is the tracked handoff file. On the first main-session
`UserPromptSubmit`, the existing prompt hook injects it as context, capped at 12,000 characters.
It is injected once per session: a marker in the session's scratch directory
(`.codex-workforce/scratch/<session>/cwf-resume-injected`) stops later prompts repeating it.
It is not injected into subagents or into a Stop-feedback continuation. Replace or delete the
file when the handoff is finished; nothing executes its contents.

### Not yet measured

- Whether Codex fires UserPromptSubmit for a Stop continuation (handled either way: the
  feedback prefix keeps it from being tagged as an ask).
- None for the four shipped events; live payloads were measured on 2026-11-11.
- `--ephemeral` sends null transcript paths; the hook now reports "not judged" rather than
  treating that as a pass.

## Routing a task to the right agent

This mirrors claude-workforce's dispatch line, which its `UserPromptSubmit` hook injects
(`/home/francis/lab/claude-workforce/workforce/bin/wf-task-tag` § `DISPATCH_NO_ORG` /
`DISPATCH_LINE`). Codex has no router and a custom agent cannot restrict tools, so this is
**prose-only guidance, never a gate** — nothing refuses and nothing blocks. It exists because
the main session is what decides, and it works **whether or not this project has an org**.

**No org chart** (the ordinary case; `.codex-workforce/org-chart.md` absent, or present
without the `AUTO-GENERATED by` marker): a job in the message goes to a **background plain
subagent**, so this session stays free for the next message. Work inline only when the answer
is already in hand or the job is a few tool calls — data in hand that answers the question is
itself the answer.

**With an org chart**: the job goes to the employee whose description fits, spawned as a
background plain subagent; when the chart names Leads, use the lowest node whose scope covers
it.

Which agent for which job, while this package has no audited org:

| The job | Spawn |
|---|---|
| Code that changes files — a feature, fix, refactor, or its tests | `cwf-implementer` |
| A code approach that needs deciding **before** writing | `code-design-advisor` |
| A review of code that already landed (dead code, duplication, complexity) | `deadcode-gardener` |
| What a skill block does, who wrote a directive, whether a conversion kept a workflow | `cwf-content-classifier`, `cwf-provenance-analyst`, `cwf-conversion-auditor` |
| Whether a rule is actually enforced; whether a role should exist | `cwf-doctrine-auditor`, `cwf-headcount-skeptic` |
| Whether a handbook is followable; what would block an audit | `cwf-handbook-cold-reader`, `cwf-settings-scout` |
| Reading, searching, research, or a few tool calls | inline, or the built-in `explorer` |

`cwf-implementer` exists because the pinned upstream set has **no** code-writing employee —
all nine are advisors. Upstream's own answer is that code work goes to a plain subagent until
an audit hires engineers; this agent is the Codex-side stand-in for that, with a handbook that
requires `changed:` / `ran:` / `not run:` / `risk:`.

**Every dispatch is one-shot**: name the agent type, spawn it, read its report, close it with
`close_agent`. An order names only tools the session actually exposes; Codex cannot enforce a
per-agent allowlist, so say so in the order rather than implying a restriction the host lacks.

**Stop rather than guess.** Two candidates tied → name both and ask one plain-text question.

## Layout

- `upstream/claude-workforce/`: unmodified copies of claude-workforce files at the commit in
  `upstream/claude-workforce/UPSTREAM.md`. **Never edit these.** Refresh with
  `scripts/sync-upstream [COMMIT]`; `tests/` fails if they drift from their checksums.
- `cwf/lib/cwf_codex.py`: the adapter. Converts Codex rollout JSONL into Claude-shaped
  transcript rows, fills `scratchpad_dir`, moves the issue ledger and widen's PERF/handoff
  paths to `.codex-workforce/`, points widen's instrument list at Codex skills and agents,
  replaces the injected Claude-only wording, and loads upstream modules with those patches
  applied to every copy (including the ones wf-widen loads for itself).
- `cwf/lib/cwf_juror.py`: the juror. Upstream's agent-hook prompt (read with `ast`, never
  executed) with the Claude-only phrases replaced, run as
  `codex exec -s read-only -c features.hooks=false -p ${CWF_JUROR_PROFILE:-glm}`.
- `cwf/bin/cwf-hook`: the hook entry point. `cwf/bin/cwf-step`: runs one upstream hook per process.
- `cwf/skills/cwf-*/`: the nine shipped skills — seven generated from upstream plus
  `cwf-dev` and `cwf-timezone`, authored here in `cwf/skills-src/` — all produced by
  `scripts/build-skills`. `cwf-timezone` writes `shell_environment_policy.set.TZ` in the
  user `config.toml`, the key Codex passes to every command it runs.
  This is the **source**; the installers copy it to `~/.agents/skills` (user) or
  `.agents/skills` (project). Nothing shipped is committed under a dot-directory.
- Scope and precedence (measured on codex-cli 0.168.0, 2026-11-13): agents and skills can be
  installed in **both** roots at once — `~/.codex/agents` + `~/.agents/skills` for the user,
  `.codex/agents` + `.agents/skills` for the project. Both visible in one session. **When the
  same agent name exists in both, the user-scope copy wins** (measured: 8/8 replies from the
  user copy, none from the project copy). So a project that must override a shipped agent
  needs a *different* name, not a same-named file.
- `cwf/agents/*.toml`: the ten Codex custom agents. Nine are generated from the pinned
  upstream `AGENT.md` handbooks; `cwf-implementer` is authored here (`cwf/agents/cwf-implementer.md`)
  because the pinned set has no code-writing employee. Both installers copy them into
  `.codex/agents/`.
- `cwf/bin/wf-code-eval`, `wf-map`, `wf-census`, `wf-settings-apply`: portable copies of the
  scripts the code-evaluator and records-code-map skills call (`wf-settings-apply` is
  `wf-code-eval`'s sibling for its link-refusal check), generated by `scripts/build-skills`.
- `cwf/bin/cwf-sync`: mirrors this repo's tree into the user-root install after a change, the
  port of `bin/sync --personal`. Plans by default; `--execute` writes; `--check` exits 1 on
  drift. Never creates an install that was not already there, and **prunes only paths a
  previous run recorded placing** — never by name, so a user's own `cwf-*` skill survives.
- `cwf/model-catalog.json` and `cwf/bin/cwf-model-catalog`: the recommended OpenRouter
  models and the tool that installs them into a Codex config. Both installers run
  `cwf-model-catalog install`, which writes a merged catalog plus an `openrouter` profile
  and prints `codex --profile openrouter`. It never writes an API key and never changes the
  default model; `cwf-model-catalog default MODEL` does that, explicitly.
- `RESUME.md`: the tracked session handoff, injected once by the prompt hook.
- `.codex-workforce/` (git-ignored): per-session scratch files and the issue ledger.
- `tests/test_senses.py`: `python3 -m unittest discover -s tests -v`. No network, no model calls.

## Rules

- Stay out of `.claude/` and `~/.claude/` entirely. Claude Code and claude-workforce live there.
- Do not write state into `.codex/` or `.agents/`; Codex's workspace-write sandbox blocks
  writes there. State goes in `.codex-workforce/`.
- Prefix skills, scripts and scratch files with `cwf-` so they never collide with
  claude-workforce's `wf-` names.
- Change behaviour in `cwf/`, never in `upstream/`. If upstream logic must change, that is a
  claude-workforce change, made there and re-synced.
- Run the tests after every change to `cwf/` or `.codex/hooks.json`.
- Commit only the package: `AGENTS.md`, `RESUME.md`, `.codex/hooks.json`, `cwf/`,
  `scripts/`, `tests/`, `upstream/`, `install`, `install.ps1`, `manifest.txt`, `VERSION`,
  `CHANGELOG.md`, `.gitignore` (and a README and LICENSE when they exist).
- Versioning: `VERSION` holds the release (`0.1.13`). Any change to a file in `manifest.txt`
  bumps it and adds a `CHANGELOG.md` entry. Every new runtime file goes in `manifest.txt`;
  `tests/test_install.py` fails if one is missing.
  Files left by the tools used to build it (Claude Code, Crush discovery probes, opencode,
  playwright-mcp, agent-say) belong in `.gitignore`. When a new tool or folder shows up, add
  it there and to `INFRA` in `tests/test_senses.py`; a new package folder goes in the
  test's `allowed` set.

## Settings

| Variable | Default | Effect |
|---|---|---|
| `CWF_JUROR` | `on` | `off` skips the juror; the turn is reported as "not judged" |
| `CWF_JUROR_PROFILE` | `glm` | Codex profile the juror runs on (`deepseek`, `glm`, `kimi`) |
| `CWF_JUROR_TIMEOUT` | `150` | seconds before the juror gives up (the turn is then reported "not judged", not silently allowed) |
| `CWF_DEBUG` | unset | logs each raw and normalised payload to `.codex-workforce/debug/`, and adds a traceback to adapter failures |

## Known gaps

- Codex custom agents load from `.codex/agents/*.toml`, but they cannot enforce a per-agent
  tool allowlist or `disallowedTools:`. The generated TOML states that limit in every
  `developer_instructions`; workforce guarantees that depend on those fields are prose and
  detection only on this host.
- On this machine Codex's sandbox gives `/tmp` its own view; work done under `/tmp` inside a
  Codex session does not persist. Test projects belong outside `/tmp`.
