# codex-workforce

A workforce system for OpenAI Codex CLI, ported from claude-workforce
(github.com/odysseyalive/claude-workforce). Codex is the only supported host. Crush
compatibility was cut on 2026-11-11; the Crush probing remains historical discovery evidence,
not a product target.

## Current state: bare-metal senses

The claude-workforce sensory layer is wired into Codex sessions in this repository through
`.codex/hooks.json`. It is verified by `tests/`, by replaying real Codex rollouts, and by live
Codex sessions in this repository on 2026-11-11. The hooks require the trust step below, and
the prompt, SubagentStart, Stop and SubagentStop payloads have all been observed live.

| Codex event | Runs | Does |
|---|---|---|
| UserPromptSubmit, SubagentStart | `cwf/bin/cwf-hook prompt` -> `wf-task-tag` | tags the ask with the senses that settle it, writes the asks checklist, opens issues |
| Stop, SubagentStop | `cwf/bin/cwf-hook stop` -> `wf-turn-ledger`, `wf-widen`, juror | counts the turn's evidence, blocks a reply whose claims lack it, and on flagged turns asks a read-only `codex exec` juror |

The hooks only run after they are trusted: open `/hooks` in an interactive Codex session in
this repository and trust the four entries. Re-trust after any change to `.codex/hooks.json`.
The hook commands find `cwf/` through `git rev-parse --show-toplevel`, so this directory must
stay a git repository.

### First live run

1. `CWF_DEBUG=1 codex` in this repository, then `/hooks`, and trust all four entries.
2. Ask, in one sentence and telling it not to look: *"Without running anything, is there a
   file named zzz-probe.txt in this repo?"*
3. Expect: a Stop block whose feedback starts "Stop hook feedback:", Codex continuing and
   enumerating (find, ls or rg), then a clean end with no second block.
4. Check `.codex-workforce/issues/` gained no issue from the feedback text, and
   `.codex-workforce/debug/<session>.jsonl` holds the raw payloads Codex sent.

### Session handoff

`RESUME.md` at the repository root is the tracked handoff file. On the first main-session
`UserPromptSubmit`, the existing prompt hook injects it as context, capped at 12,000 characters.
It is not injected into subagents or into a Stop-feedback continuation. Replace or delete the
file when the handoff is finished; nothing executes its contents.

### Not yet measured

- Whether Codex fires UserPromptSubmit for a Stop continuation (handled either way: the
  feedback prefix keeps it from being tagged as an ask).
- None for the four shipped events; live payloads were measured on 2026-11-11.
  The `--ephemeral` transcript-null case remains an adapter gap (F03 in `audit/FINDINGS.md`).

## Layout

- `upstream/claude-workforce/`: unmodified copies of claude-workforce files at the commit in
  `upstream/claude-workforce/UPSTREAM.md`. **Never edit these.** Refresh with
  `scripts/sync-upstream [COMMIT]`; `tests/` fails if they drift from their checksums.
- `cwf/lib/cwf_codex.py`: the adapter. Converts Codex rollout JSONL into Claude-shaped
  transcript rows, fills `scratchpad_dir`, moves the issue ledger to `.codex-workforce/issues`,
  points widen's instrument list at Codex skills and agents, and loads upstream modules with
  those patches applied to every copy (including the ones wf-widen loads for itself).
- `cwf/lib/cwf_juror.py`: the juror. Upstream's agent-hook prompt (read with `ast`, never
  executed) with the Claude-only phrases replaced, run as
  `codex exec -s read-only -c features.hooks=false -p ${CWF_JUROR_PROFILE:-glm}`.
- `cwf/bin/cwf-hook`: the hook entry point. `cwf/bin/cwf-step`: runs one upstream hook per process.
- `.agents/skills/cwf-blueprint/`: the blueprint skill, generated by `scripts/build-skills`.
- `RESUME.md`: the tracked session handoff, injected once by the prompt hook.
- `.codex-workforce/` (git-ignored): per-session scratch files and the issue ledger.
- `tests/test_senses.py`: `python3 -m unittest discover -s tests -v`. No network, no model calls.

## Rules

- Stay out of `.claude/` and `~/.claude/` entirely. Claude Code and claude-workforce live there.
- Do not write state into `.codex/` or `.agents/`; Codex's workspace-write sandbox blocks
  writes there. State goes in `.codex-workforce/`.
- Prefix skills, scripts and scratch files with `cwf-` so they never collide with
  claude-workforce's `wf-` names.
- Change behaviour in `cwf/`, never in `upstream/`. If upstream logic must change, that is a
  claude-workforce change, made there and re-synced.
- Run the tests after every change to `cwf/` or `.codex/hooks.json`.
- Commit only the package: `AGENTS.md`, `RESUME.md`, `.agents/skills/`, `.codex/hooks.json`, `cwf/`,
  `scripts/`, `tests/`, `upstream/`, `install`, `install.ps1`, `manifest.txt`, `VERSION`,
  `CHANGELOG.md`, `.gitignore` (and a README and LICENSE when they exist).
- Versioning: `VERSION` holds the release (`0.1.1`). Any change to a file in `manifest.txt`
  bumps it and adds a `CHANGELOG.md` entry. Every new runtime file goes in `manifest.txt`;
  `tests/test_install.py` fails if one is missing.
  Files left by the tools used to build it (Claude Code, Crush discovery probes, opencode,
  playwright-mcp, agent-say) belong in `.gitignore`. When a new tool or folder shows up, add
  it there and to `INFRA` in `tests/test_senses.py`; a new package folder goes in the
  test's `allowed` set.

## Settings

| Variable | Default | Effect |
|---|---|---|
| `CWF_JUROR` | `on` | `off` skips the juror (the deterministic checks still run) |
| `CWF_JUROR_PROFILE` | `glm` | Codex profile the juror runs on (`deepseek`, `glm`, `kimi`) |
| `CWF_JUROR_TIMEOUT` | `150` | seconds before the juror gives up (the turn is then allowed) |
| `CWF_DEBUG` | unset | logs each raw and normalised payload to `.codex-workforce/debug/`, and adds a traceback to adapter failures |

## Known gaps

- The text wf-task-tag injects is written for Claude Code: it names `AskUserQuestion` and
  `shutdown_request`, which Codex does not have. Adapting it is the next job.
- Codex did not list a custom agent from `.codex/agents/` in testing (2026-11-10); confirm how
  Codex loads custom agents before building employees on them.
- On this machine Codex's sandbox gives `/tmp` its own view; work done under `/tmp` inside a
  Codex session does not persist. Test projects belong outside `/tmp`.
